{# 2. What it is #}

{{ _('What it is') }}

{{ _("Seleno is a complete telescope system: the control software, plus the motor mounts and electronics that drive the telescope. Together they let you control a network of telescopes, at any time, from anywhere on the globe. Image the planet, star, nebula or galaxy of your choice from the comfort of your own home.") }}

{{ _("Seleno's automated system runs observation programmes without human intervention, capturing all the different frames and image types needed to produce stunning astrophotography. A live camera view, fine camera settings, histograms and individual motor controls are also available from the interface.") }}

{{ _("A core focus of Seleno is making astrophotography more accessible to the wider population, who may be interested in space but struggle with the complex systems currently available. An advanced mode is also available for more experienced users.") }}

{{ _("Seleno's star map makes finding and tracking objects simple. Search for an object by name, and the telescope will slew to face it and track it across the sky, keeping up with the rotation of the earth.") }}

{{ _("Seleno doesn't need the internet at the telescope, either. Each telescope has a small built in screen and buttons, so it can be set up and operated on the spot, even at a remote dark site with no signal.") }}

{{ _("Finally, a booking system lets you rent time on telescopes around the globe, so the object you want to image is always up from at least one of them.") }}

{# 7. A deeper look #}

{{ _('A deeper look') }}

{{ _('For engineers and recruiters') }}

{{ text_slot('Intro sentence: full stack project, designed and built end to end.') }}

Software

{{ _("Seleno's software has three parts: a Flask server, a Python client on each telescope's Raspberry Pi, and C++ firmware on the ESP32. The server uses SQLAlchemy over SQLite, Jinja2 templates, Bootstrap 5 and plain JavaScript, with a custom canvas star map and some compute heavy code in C++. The interface is available in English and Spanish, with about 1,750 translated strings.") }}

{{ _('Server and interface') }}

{{ _("Basic mode lets you pick a curated target, check focus, take a test shot and capture, with a live view while imaging. Advanced mode adds custom coordinates, direct console output, full camera settings, a live histogram and stream controls. Both modes can run imaging plans, which are lists of steps such as go to, wait, lights, darks, flats, bias and video. Each plan is validated against a schema and the camera's capabilities, and its running time is estimated from overheads learned on earlier plans.") }}

{{ _("Bookings are converted to UTC and checked against the owner's rules inside a write locked SQLite transaction, so a multi date request either fully succeeds or rolls back. Owners approve each booking, every change is audit logged, and a watchdog stops any plan when the slot ends. SumUp payments are built but still in sandbox. A new telescope gets a random token that is stored only as a hash and shown once, and it stays inactive until an admin approves it.") }}

{{ _('Telescope node') }}

{{ _("Each node is an asyncio Python client, with slow work pushed to threads. It connects out over two WebSockets, one for commands and one for live view, so it works behind a home router with no port forwarding. Commands run in separate lanes and carry request IDs, so a long exposure never blocks a slew and a stop always gets through. A single thread owns the camera through gphoto2. Live view frames are reencoded on the Pi, skipped when unchanged and stepped down on slow links. Photos upload from a queue saved on disk, JPEGs first and RAW later, so nothing is lost across restarts or dropped connections.") }}

{{ _("The Pi also plate solves locally with ASTAP, records video including uncompressed SER, and checks every go to against the Sun, the horizon and dead zones. Offline mode runs all of this without the server, with a phone page protected by a code on the front panel. Nodes can update themselves from a webhook, and every update is reviewed by an admin first.") }}

{{ _('Firmware') }}

{{ _("The ESP32 runs C++ on the Arduino framework, built with PlatformIO and FreeRTOS. The Pi sends newline delimited JSON over UART at 921600 baud, and each reply echoes the command's ID. A 20 kHz timer interrupt uses phase accumulators to produce exact step rates, which keeps tracking drift minimal, while a 1 ms timer runs trapezoidal ramps and multi segment slew paths that can curve around the Sun. Microstepping and TMC2209 chopper mode are chosen per move, fine and quiet for tracking, coarse and strong for slews. Pointing uses a least squares model of up to six terms, fitted from plate solves or stars centred by hand, along with three point polar alignment, refraction and precession corrections.") }}

{{ _('Stacking in the browser') }}

{{ _("The album's stacking engine runs entirely in the browser with JavaScript and web workers, switching between memory, OPFS and streaming modes so huge stacks still fit. Pass one calibrates each frame with master darks, flats and bias, measures the stars and picks the sharpest frame as the reference. Frames that are blurred, stretched or star poor are rejected using robust statistics, and the rest are aligned to the reference. Pass two debayers and resamples each frame, matches its background and noise to the reference, weights it by noise and combines everything with iterative winsorized sigma clipping. The output is a master FITS file with a preview, a coverage map and a per frame report of what was rejected and why.") }}

{{ _('Challenges and lessons') }}

{{ _("The star map was my hardest problem, and the current one is its third version. My first attempt in Three.js drew every star as a white dot or a streak falling from the zenith. I later found the cause: I had treated right ascension as hours when the database stored degrees, so every position was 15 times too large. Inexperience with Three.js made it much harder to debug, so I replaced it with a custom canvas renderer.") }}

{{ _("What's next") }}

{{ _("I still need to finish payments and add the Pi runner for fully automated plans. After that I would like to track satellites, asteroids and dwarf planets, and add focuser control. A custom plate solver is a maybe. Ideas are welcome on the GitHub issue tracker.") }}

Hardware

{{ _("Seleno runs on a custom four layer PCB that I designed myself in KiCad. It measures 85 × 50 mm and connects the motor drivers, motors, Raspberry Pi Zero 2 W, buttons, screen, IMU and power supply in a clean, space efficient way. The ESP32 handles low level hardware control, such as the motors, screen and LEDs, while the Pi Zero 2 W handles higher level control, network interfacing and camera control.") }}

{{ _('Why I built it') }}

{{ _("Designing my own board let me add features that most telescope control systems don't have, such as a screen, and gave advanced users more control over the system than other controllers offer. It also let me make the whole product much smaller, and it was the best way to teach myself PCB manufacturing, soldering and KiCad.") }}

{{ _("The board's two standout features are that it works both online, connected to Seleno's servers, and offline, and that it offers much higher customisation than commercial boards. The whole node also runs from a single socket, with reverse polarity protection, a fuse against overcurrent, and traces sized for the current they carry.") }}

{{ _('How it was made') }}

{{ _("I taught myself KiCad to do the schematic and layout. For v0.1 to v0.7, JLCPCB printed only the bare board and I assembled everything else myself. For v0.8, JLCPCB made the PCB and did most of the assembly, leaving about 20 percent for me to finish by hand. Only three revisions were actually made: v0.2, v0.5 and v0.8, which is the current board.") }}

{{ _('Revisions') }}

  • {{ _("v0.1 was my first PCB ever, and mostly a way of learning KiCad.") }}
  • {{ _("v0.2 shrank the board to 50 × 85 mm.") }}
  • {{ _("v0.3 to v0.5 replaced the ESP32 dev board plug in with a smaller module.") }}
  • {{ _("v0.6 to v0.8 replaced every remaining module except the ESP32 with bare ICs, changed the screw connectors to JST connectors, and added proper power handling circuitry. They also changed the link to the Pi from USB to UART over GPIO. USB support remains in the firmware in case I want to use it again.") }}

{{ _('Challenges and lessons') }}

{{ _("Soldering 0402 passives (1.0 × 0.5 mm) was really difficult. I tried a hot air gun, but found I was faster with a soldering iron and a microscope. The 1 mm pitch JST SH connectors also took a lot of patience. On an older board, probably v0.5, I accidentally pulled a buck converter pad off the PCB and had to learn how to replace it.") }}

{{ _("I didn't realise on the early versions how much trace width matters. Traces carrying higher currents need to be wider, while less critical signals like GPIO can stay thin. I also learned the importance of test pads and debugging. That was the main focus of v0.8, so I can debug the board easily instead of buying a new one every time.") }}

{{ _('Licence') }}

{{ _("I haven't decided to make the PCB design public. The current plan is for it to be source available rather than open source. People could make it at home for personal use but not sell it, as laid out in the licence.") }}

{{ _("What's next: v1.0") }}

{{ _("For v1.0 I want to remove the Raspberry Pi Zero 2 W completely and do everything on the board. The hardest challenge will be camera control, including livestreaming, from the ESP32. I plan to use the new ESP32-S31, which supports USB high speed and has enough processing power to host the entire client. Cutting the 5V adapters, the Pi and other circuitry should save between £20 and £30 per board.") }}

{{ _("I'd also like to add a mirror heating port, so everything plugs into the main enclosure and only one socket is needed. I'm considering power monitoring and feedback as well, so that on battery you can estimate whether an observation session will finish.") }}
